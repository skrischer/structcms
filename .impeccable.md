# StructCMS Design Context

## Design Context

### Users
Content editors and developers managing websites through a headless CMS admin interface. They work in focused sessions — creating pages, editing content, managing media, configuring navigation. The tool should feel like a natural extension of their workflow, not an obstacle. Non-technical users (editors) should feel confident without training; developers should feel at home with the precision and predictability.

### Brand Personality
**Warm, intuitive, reliable.**

StructCMS is approachable without being casual. It communicates competence through clarity, not complexity. The interface should feel like a well-organized workspace — everything in its place, nothing unnecessary, but never cold or sterile.

### Emotional Goals
- **Clarity & calm** — No visual stress. Everything is scannable and predictable.
- **Efficiency & flow** — The tool disappears behind the task. Zero friction.
- **Trust & control** — The user always understands what's happening and feels in charge.

### Aesthetic Direction

**Visual tone:** Clean, warm-neutral, content-first. Minimal but not austere — subtle warmth in the gray palette (Slate tones) prevents clinical coldness.

**References:**
- Notion / Linear: Clean, monochromatic, content-first. Minimal visual noise.
- The interface should feel modern and purpose-built, not assembled from generic components.

**Anti-references:**
- NOT WordPress: No visual clutter, no legacy patterns, no overloaded toolbars.
- NOT generic SaaS: No gratuitous gradients, no dark-navy-with-neon-accent palettes.

**Theme:** Light mode only. The Slate gray palette provides warmth through its blue undertone without being overtly colorful.

### Design Principles

1. **Content is the star.** The interface frames the content, never competes with it. Every pixel of chrome should justify its existence.

2. **Quiet confidence.** Professional without being corporate. Warm without being playful. The design should feel authoritative through restraint, not decoration.

3. **Predictability over novelty.** Consistent patterns reduce cognitive load. Users should never wonder "where did that go?" or "what does this do?" Surprise is the enemy of productivity.

4. **Density with clarity.** Show maximum useful information without clutter. Achieve this through typography hierarchy and spacing rhythm, not by hiding content behind interactions.

5. **Accessible by default.** WCAG 2.1 AA compliance is the baseline, not an afterthought. Focus rings, keyboard navigation, color-plus-icon status, visible labels — baked into every component.

## Design System Summary

### Color Palette

| Role | Value | Token |
|------|-------|-------|
| Primary | `#2563EB` | `--admin-primary-600` |
| Primary Hover | `#1D4ED8` | `--admin-primary-700` |
| Primary Tint | `#EFF6FF` | `--admin-primary-50` |
| Page Background | `#F8FAFC` | `--admin-surface-page` |
| Card Surface | `#FFFFFF` | `--admin-surface-card` |
| Primary Text | `#1E293B` | `--admin-gray-800` |
| Secondary Text | `#64748B` | `--admin-gray-500` |
| Labels | `#475569` | `--admin-gray-600` |
| Borders | `#E2E8F0` | `--admin-gray-200` |
| Success | `#22C55E` / `#15803D` | `--admin-success-500/700` |
| Error | `#EF4444` / `#B91C1C` | `--admin-error-500/700` |
| Warning | `#F59E0B` / `#B45309` | `--admin-warning-500/700` |

### Typography

- **UI Font:** Inter (Google Fonts)
- **Code Font:** JetBrains Mono
- **Display:** 30px/700, -0.02em tracking
- **H1:** 24px/600, -0.01em
- **H2:** 20px/600, -0.01em
- **H3:** 16px/600
- **Body:** 14px/400
- **Label:** 13px/500, 0.01em
- **Caption:** 12px/400, 0.01em

### Spacing Rhythm

Base unit: 4px. Key stops: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.

- **Element gaps:** 4-8px
- **Component padding:** 12-16px
- **Section padding:** 24-32px
- **Page margins:** 40-48px

### Component Patterns

- **Buttons:** 5 variants (primary, secondary, ghost, destructive, destructive-outline), 3 sizes (sm/default/lg)
- **Inputs:** 36px height, 6px radius, 3px focus ring
- **Cards:** White surface, 1px border, 8px radius, subtle shadow
- **Sidebar:** 260px expanded / 64px collapsed
- **Icons:** Lucide React, 20px default, 1.5px stroke

### Interactions

- Micro-interactions: 150ms
- State changes: 200ms
- Panel/modal animations: 300ms
- Easing: `cubic-bezier(0.4, 0, 0.2, 1)`

## Canonical Design System Files

- **Full spec:** `design-system/MASTER.md` (root-level, generated by ui-ux-pro-max)
- **Admin-specific:** `design-system/structcms-admin/MASTER.md` (authoritative for all admin components)
- **CSS tokens:** `packages/admin/src/styles/admin.css` (runtime implementation)

> **Note:** When there is a conflict between the two MASTER.md files, `design-system/structcms-admin/MASTER.md` takes precedence — it reflects the actual implemented design system (Inter font, blue-only primary, Slate grays). The root `design-system/MASTER.md` contains some legacy values (Fira Code/Sans, orange CTA) that do not match the implementation.
